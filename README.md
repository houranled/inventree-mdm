# 创建仓库后请手动完成以下配置(该内容用于新仓库提醒，后续可删除)

## 1. 协作者/团队权限（必要）

`设置 → 协作者 / 团队`，把相关人员加入并分配权限。

## 2. 仓库 → 高级设置
- 关闭：启用时间跟踪（工单）、软件包、变基后快进（合并方式）、变基后创建合并提交（合并方式）、仅快进（合并方式）
- 开启：默认允许维护者编辑、允许通过变基更新合并请求分支、默认合并后删除合并请求分支

## 3. 分支保护（已配置，可按需修改）
`设置 → 分支 → 分支保护 → 添加规则`，规则名如 `{main}`：
- **必需审批数：1**（按团队要求填写）——**不填则为 0，PR 无需审批即可合并**
- 审批白名单、合并白名单、状态检查：按需配置

## 4. 工作流 密钥/变量（组织级已统一配置，仓库级别可以按需覆盖）

`设置 → 工作流-变量和密钥`：

| 名称 | 用途 |
|---|---|
| `secrets.WECHAT_WEBHOOK` | 企业微信群机器人 webhook，通知必配 |
| `vars.DEFAULT_RUNNER` | build 默认 runner 标签 |

## 5. 公开访问（非必要）

`设置 → 公开访问`：控制组织以外的人可查看的范围。

## 6. 根目录构建脚本 与 工作流手动发布版本（重要）

CI「构建并测试/发布」job 自动调用仓库**根目录**的构建脚本（脚本文件名只能固定如下！）：

- Windows runner：`build.bat`（`test.bat` 自动测试可选）
- Linux/其他 runner：`build.sh`（`test.sh` 自动测试可选）

脚本第一个入参为自动生成的版本号, 按需使用； 需自行完成脚本逻辑：编译、把产物输出到 `Output/` 目录、失败返回非 0、不弹窗不阻塞。**根目录没有对应脚本时构建会被静默跳过**，若想发版请在根目录添加该脚本。

### 通过工作流手动发布版本

1. 仓库 → 顶部 **工作流** → 左侧 **scope_workflows → 主工作流** → **运行工作流**
2. 「使用工作流从」选 `main`；「构建平台」保持默认工作流运行器变量（`vars.DEFAULT_RUNNER`）
3. 「要发版的 commit hash」填写 `main` 分支当前提交的完整 hash（留空则只做构建/测试，不发版）
4. 运行后工作流自动把 `Output/` 产物上传为 release assets，仓库「发布」页可见

也可直接 push 一个 tag 触发发版。详见 `.profile/doc/自动化工作流说明.md` 第 3.3、4 章。
